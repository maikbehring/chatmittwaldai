ChatGPT bleibt oft die stärkere Allzweck-KI — und das ist okay.

OpenAI steckt enorme Mittel in sehr große Modelle und in ein Nutzererlebnis, das über Jahre poliert wurde. In reiner Sprachqualität, Kreativität und „es klappt einfach“ liegt ChatGPT deshalb häufig vorne. Wer das erwartet, sollte ehrlich damit rechnen.

Open WebUI bei mittwald ersetzt ChatGPT nicht Eins-zu-eins — es gibt euch etwas anderes: souveräne KI unter eurer Kontrolle, mit dem vertrauten Chat-Gefühl, aber ohne dass Firmendaten durch eine öffentliche Konsum-Cloud wandern müssen.

1. Was bekommst du?

Kurz: ChatGPT-Gefühl — aber unter deiner Kontrolle.

Open WebUI ist eine Chat-Oberfläche, die du selbst betreibst. Die KI-Modelle kommen von mittwald AI Hosting (OpenAI-kompatible API, Rechenzentrum in Deutschland). Du bestimmst Nutzer, Modelle und welche Firmendokumente die KI kennen darf.

Für dich bedeutet das

  • Chat, Texte, Analysen — wie gewohnt
  • Optional: aktuelle Infos per Websuche
  • Optional: Antworten aus euren PDFs & Handbüchern
  • Eigene Nutzerverwaltung, kein öffentliches ChatGPT-Konto

Was du brauchst

  • mStudio-Projekt mit Container Hosting
  • AI Hosting-Tarif (Starter reicht zum Testen)
  • Einen API-Key aus dem mStudio
  • Ca. 10 Minuten für den Schnellstart
Tipp für Nicht-Techniker Nutze den Schnellstart unten. Du klickst dich durchs mStudio — Terminal und Docker-Kenntnisse sind nicht nötig.

2. Schnellster Weg empfohlen

Managed Deployment: Open WebUI wird beim Anlegen des API-Keys mitinstalliert.

  1. AI Hosting buchen Im mStudio AI Hosting aktivieren. Der Starter-Tarif reicht zum Ausprobieren. Details: AI Hosting.
  2. API-Key anlegen + Open WebUI mitinstallieren Im mStudio unter AI Hosting einen API-Key anlegen. Wenn dein Produkt Container unterstützt, aktiviere die Option, Open WebUI automatisch mitzuinstallieren.
  3. Admin-Benutzer direkt im Dialog setzen Im selben Dialog legst du den Admin-Benutzer (E-Mail/Passwort) fest. So startet Open WebUI nicht „blank“ und öffentlich im Netz — der erste Zugang ist schon geschützt, bevor du die Oberfläche öffnest. Neue Selbst-Registrierungen sind damit von Anfang an nicht nötig (bzw. bleiben gesperrt).
  4. Domain verbinden & anmelden Weise dem Container eine Domain/Subdomain zu (z. B. ki.meine-firma.de) und melde dich mit dem Admin-Zugang aus dem Dialog an.
  5. Ersten Chat starten Wähle als Default-Modell Qwen3.6-35B-A3B-FP8 (Allrounder) und stelle eine Testfrage. Wenn eine Antwort kommt: Verbindung zu AI Hosting steht.
Warum der Admin im Dialog? Ohne vorab gesetzten Admin könnte Open WebUI kurzzeitig mit offener Erst-Registrierung erreichbar sein. Der AI-Hosting-Dialog verhindert genau das: Admin zuerst, dann öffentlich erreichbar.
Fertig in ~10 Minuten Ab hier kannst du schon produktiv chatten. Websuche und Wissensdatenbank sind optional — aber genau das macht das „ChatGPT-Plus-Gefühl“.

3. Manuell im mStudio (falls kein Auto-Install)

Schritt für Schritt über die Oberfläche — CLI-Variante einklappbar darunter.

  1. Container erstellen Projekt → Container → Container erstellen. Beschreibung z. B. „Open WebUI“.
  2. Image angeben Image: ghcr.io/open-webui/open-webui:main
    Entrypoint und Command: unverändert lassen.
  3. Volume für Daten Persistentes Volume auf /app/backend/data — speichert Chats, Einstellungen und hochgeladene Dokumente. Ohne Volume gehen Daten bei Updates verloren.
  4. Umgebungsvariablen setzen 
    PORT=8080
WEBUI_NAME=mittwald AI Chat
ENABLE_SIGNUP=false
OPENAI_API_BASE_URL=https://llm.aihosting.mittwald.de/v1
OPENAI_API_KEY=dein_api_key_hier
    Beim manuellen Weg: zuerst Admin in Open WebUI anlegen, danach ENABLE_SIGNUP=false setzen (ENV oder Admin Panel) — sonst steht die Instanz kurz mit offener Registrierung im Netz. Beim Managed-Weg (API-Key-Dialog) ist der Admin bereits im Dialog gesetzt.
  5. Port & Domain Port 8080 freigeben und eine Domain auf den Container legen. Danach erreichst du Open WebUI unter https://deine-domain/. Volumes werden im Projekt-Backup mitgesichert.
Alternative für Profis: CLI (mw container run) 
mw container run \
  --name openwebui \
  --description "Open WebUI - AI Chat Interface" \
  --publish 8080:8080 \
  --env "OPENAI_API_BASE_URL=https://llm.aihosting.mittwald.de/v1" \
  --env "OPENAI_API_KEY=dein_api_key_hier" \
  --env "WEBUI_NAME=mittwald AI Chat" \
  --env "ENABLE_SIGNUP=false" \
  --volume "openwebui-data:/app/backend/data" \
  --create-volumes \
  ghcr.io/open-webui/open-webui:main
Danach Domain zuweisen.
Alternative: docker-compose.yml + mw stack deploy 
services:
  openwebui:
    image: ghcr.io/open-webui/open-webui:main
    ports:
      - "8080:8080"
    volumes:
      - "openwebui-data:/app/backend/data"
    environment:
      PORT: "8080"
      WEBUI_NAME: "mittwald AI Chat"
      OPENAI_API_BASE_URL: "https://llm.aihosting.mittwald.de/v1"
      OPENAI_API_KEY: "dein_api_key_hier"
      ENABLE_SIGNUP: "false"
volumes:
  openwebui-data: {}
Im Verzeichnis mit der Datei: mw stack deploy
Verbindung nachträglich im Admin Panel
  1. Profil → Settings → Connections
  2. OpenAI API → neue Verbindung
  3. Base URL: https://llm.aihosting.mittwald.de/v1
  4. API-Key eintragen und speichern
Open WebUI erkennt danach alle verfügbaren Modelle automatisch.

4. Welches Modell wofür?

Das ist der Schlüssel zum ChatGPT-Gefühl: das richtige Modell für die Aufgabe.

Default-Empfehlung Setze Qwen3.6-35B-A3B-FP8 als Standardmodell. Starkes Reasoning, Vision, großer Kontext — und günstiger als die großen 120B-Modelle. Regel von mittwald: immer mit dem kleinsten ausreichenden Modell starten.
Aufgabe im Alltag Modell Warum
Standard-Chat, E-Mails, Texte (Allrounder) Qwen3.6-35B-A3B-FP8 Reasoning + Vision, 256k Kontext, gutes Preis-/Leistungsverhältnis — Default
Komplexe Analysen, Fachtexte, höchste Qualität gpt-oss-120b oder Qwen3.5-122B-A10B-FP8 Große Modelle, starkes Reasoning; 122B zusätzlich Vision
Bilder verstehen (Screenshots, Fotos, Scans) Qwen3.5-122B-A10B-FP8 / Ministral-3-14B-Instruct-2512 Vision-Modalität
Massenaufgaben, Klassifizierung, Routing Qwen3.5-0.8B Schnell und kostengünstig
Diktieren statt tippen whisper-large-v3-turbo Speech-to-Text, 99+ Sprachen — aus der Chat-Liste ausblenden
Wissensdatenbank / RAG Qwen3-Embedding-8B Embedding-Modell (kein Chat)
PDF / Scan → Text GLM-OCR Dokument-OCR
RAG-Treffer nachschärfen (optional) Qwen3-VL-Reranker-2B Zweiter Schritt nach der Vektorsuche

Chat + Reasoning: gpt-oss-120b (131k), Qwen3.5-0.8B (262k), Qwen3.6-35B-A3B-FP8 (256k), Qwen3.5-122B-A10B-FP8 (245k Vision), Ministral-3-14B-Instruct-2512 (262k Vision). Spezial: Embedding Qwen3-Embedding-8B, OCR GLM-OCR, STT whisper-large-v3-turbo, Reranker Qwen3-VL-Reranker-2B.

5. Optimale Einstellungen in Open WebUI

Inhalt aus der offiziellen mittwald-Anleitung „Open WebUI mit mittwald AI Hosting“ — hier vollständig, damit du nicht hin- und herspringen musst.

Verbindung prüfen (falls nicht schon per Managed Deployment)

Beim Managed Deployment (API-Key-Dialog) ist die Verbindung bereits gesetzt. Sonst im Admin Panel:

  1. Gehe zu „Settings“ und wähle „Connections“
  2. Im Bereich „OpenAI API“ füge eine weitere Verbindung hinzu
  3. Basis-URL: https://llm.aihosting.mittwald.de/v1
  4. API-Key eintragen und speichern

Open WebUI erkennt danach automatisch alle verfügbaren Modelle.

Modelle aufräumen

  1. Admin Settings → Models
  2. Spezialmodelle ausblenden („Hide model“): whisper-large-v3-turbo, Qwen3-Embedding-8B, GLM-OCR, Qwen3-VL-Reranker-2B
  3. Default-Modell auf Qwen3.6-35B-A3B-FP8 setzen
Hinweis von mittwald Embedding-Modelle in der Modellauswahl ausblenden — sie werden von Open WebUI erkannt, lassen sich aber nicht in einem Chat verwenden.

Optimierung der Modell-Parameter (Advanced Params)

Für optimale Ergebnisse die Standard-Parameter von Open WebUI je Modell anpassen:

  1. Navigiere zum Bereich „Models“ in Open WebUI
  2. Wähle das Modell aus, das du konfigurieren möchtest
  3. Unter „Advanced Params“ setze die empfohlenen Parameter aus der jeweiligen Modell-Dokumentation, z. B. top_p, top_k und temperature

Speech-to-Text (Mikrofon / Whisper)

whisper-large-v3-turbo unterstützt über 99 Sprachen und ist für Audio-Transkription über die gehostete mittwald-API optimiert.

Konfiguration im Admin Panel

In den Admin Settings unter „Audio“:

  • Speech-to-Text Engine: „OpenAI“
  • API Base URL: https://llm.aihosting.mittwald.de/v1
  • API Key: dein API-Key
  • STT Model: whisper-large-v3-turbo

Whisper aus Chat-Modellen ausblenden

Whisper erscheint nach der Verbindung in der Modellliste, gehört aber nicht in die Chat-Auswahl (es ist für Transkription, nicht für konversationelle KI):

  1. Admin settings → Models
  2. whisper-large-v3-turbo wählen
  3. „Hide model“ aktivieren

Benutzereinstellungen (pro Nutzer, nicht Admin)

Unter Benutzereinstellungen → „Audio“:

  • Language: Sprachcode explizit setzen (z. B. de oder en)
  • Instant Auto-Send After Voice Transcription: optional aktivieren, damit Transkriptionen ohne Bestätigung gesendet werden

Empfohlene Parameter für Whisper

Im Admin Panel oder in den Chat-Einstellungen unter Additional Parameters:

  • temperature=1.0
  • top_p=1.0

Testen

  1. Mikrofon-Symbol in einem Chat anklicken
  2. In der konfigurierten Sprache sprechen
  3. Transkription läuft über /v1/audio/transcriptions — Formate: MP3, OGG, WAV, FLAC (max. 25 MB)
Tipp für Genauigkeit Sprachparameter immer explizit setzen — besonders bei nicht-deutschen Audioeingaben.

6. Websuche einrichten

Damit die KI aktuelle Infos aus dem Netz holen kann — wie bei ChatGPT mit Suche.

Einfach für die meisten

Brave Search API — kein zweiter Container nötig.

  1. API-Key bei Brave Search holen (Free Tier: ca. 2.000 Suchen/Monat)
  2. Open WebUI → Admin → Tools → Web Search
  3. Enable Web Search aktivieren
  4. Engine: brave
  5. API-Key eintragen
  6. Concurrent Requests = 1 (sonst oft 429-Fehler im Free Tier)
  7. Speichern

Souverän Profis

SearXNG als zweiter Container im selben Projekt.

  1. SearXNG-Container starten (interner DNS-Name, z. B. searxng)
  2. In SearXNG JSON-Format in settings.yml aktivieren (sonst 403)
  3. In Open WebUI Engine: searxng
  4. Query URL z. B.
    http://searxng:8080/search?q=<query>

Vorteil: keine externe Such-API, alles im eigenen Projekt.

Nutzung im Chat Websuche im Chat aktivieren (Globus-Symbol / Web-Search-Toggle). Achtung: Einstellungen im Admin-Panel überschreiben Umgebungsvariablen.
ENV-Beispiel Brave (optional, UI hat Vorrang) 
ENABLE_WEB_SEARCH=True
WEB_SEARCH_ENGINE=brave
BRAVE_SEARCH_API_KEY=dein_brave_key
WEB_SEARCH_RESULT_COUNT=3
WEB_SEARCH_CONCURRENT_REQUESTS=1

7. Kleines RAG-System (Wissensdatenbank)

Open WebUI kann Wissen in Form von Dokumenten hinterlegen (Retrieval-Augmented Generation / RAG). Die KI antwortet dann auf Basis eurer PDFs und Handbücher — nicht nur aus dem Modellwissen.

Schritt A — Embedding-Modell konfigurieren

Für performantere Verarbeitung ein Embedding-Modell von mittwald AI Hosting nutzen:

  1. Admin Settings → Documents Menüpunkt „Documents“ öffnen.
  2. Embedding Engine „OpenAI“ Im Bereich „Embedding“ im Dropdown „OpenAI“ als Embedding Model Engine wählen.
  3. Endpunkt & API-Key Endpunkt: https://llm.aihosting.mittwald.de/v1
    API-Key: dein generierter AI-Hosting-Key
  4. Embedding-Modell & Stapelgröße Unter „Embedding Model“: Qwen3-Embedding-8B
    Embedding-Stapelgröße auf 32 setzen (mittwald-Empfehlung).
  5. Retrieval feinjustieren (optional) Im Bereich „Retrieval“ die Parameter „Top K“ und „RAG Template“ nach Bedarf anpassen — für den Einstieg reichen die Startwerte.

Schritt B — Dokumente hochladen (Knowledge)

  1. Workspace → Knowledge In der linken Menüleiste zu „Workspace“ navigieren.
  2. Neue Wissensdatenbank Reiter „Knowledge“ → Button „New Knowledge“ — Name vergeben (z. B. „Firmenhandbuch“).
  3. Dokumente hochladen PDFs und Docs hochladen, die verfügbar sein sollen.
  4. Im Chat nutzen Über „Attach knowledge“ im Chat-Eingabefeld (oder #firmenhandbuch) die Wissensdatenbank anhängen.
  5. Prüfen Eine Frage stellen, die nur aus dem Dokument beantwortbar ist — so siehst du, ob RAG greift.
Ausblick, wenn es wächst Für größere RAG-Setups: AnythingLLM + Qdrant als Container-Templates im mStudio. Kein Extra-RAG-Tarif nötig — es läuft über AI Hosting + Container.

9. FAQ & Troubleshooting

Es erscheinen keine Modelle

Prüfe Base URL https://llm.aihosting.mittwald.de/v1 (mit /v1) und den API-Key. Key neu erzeugen und in Connections bzw. ENV aktualisieren. Container danach neu starten, falls ENV geändert wurde.

Websuche liefert nichts / Fehler 429

Bei Brave Free Tier: Concurrent Requests auf 1 setzen. Engine und API-Key im Admin Panel prüfen — UI-Einstellungen überschreiben ENV.

SearXNG: Fehler 403

JSON-Format in der SearXNG-settings.yml aktivieren. Ohne JSON lehnt SearXNG die Anfragen von Open WebUI ab.

Wo liegen meine Daten?

Im Volume unter /app/backend/data im mittwald-Projekt (RZ Deutschland). Projekt-Backups sichern Volumes mit. Chat-Inhalte gehen nicht an öffentliche ChatGPT-Clouds.

Was kostet das?

AI Hosting (z. B. Starter zum Testen) + Container Hosting. Die eingebaute Knowledge-/RAG-Funktion in Open WebUI braucht keinen Extra-RAG-Tarif — du zahlst die Embedding-/Chat-Nutzung über AI Hosting.

Antworten sind schwach / „nicht wie ChatGPT“

Default auf Qwen3.6-35B-A3B-FP8 stellen, Advanced Params laut Modell-Doku setzen, Websuche und Knowledge aktivieren. Für schwere Fachfragen kurz auf gpt-oss-120b oder Qwen3.5-122B-A10B-FP8 wechseln.

Glossar (Kurz)
  • API-Key — Zugangsschlüssel zu den KI-Modellen
  • Container — fertig verpackte App, die mittwald für dich betreibt
  • Embedding — wandelt Texte in Zahlenvektoren um, damit Suche in Dokumenten funktioniert
  • RAG — „Retrieval Augmented Generation“: erst relevante Docs holen, dann antworten
  • Volume — dauerhafter Speicher, der Container-Neustarts überlebt
